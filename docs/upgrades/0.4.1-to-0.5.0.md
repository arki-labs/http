# Upgrade @arki/http 0.4.1 to 0.5.0

You must act only if an alert or dashboard counts spans with error status to find thrown `HttpError` refusals below 500; everyone else can skip it.

## What changed

- A thrown `HttpError` with a status below 500 no longer sets error status on its span. It still records `failure.code`. This matches returned failures: only a fault (status 500 or higher) is an error, so an expected refusal such as an `http.idempotency` reused key (422) or a cancelled request (499) does not page anyone. A thrown 5xx `HttpError` and any other throw still set error status.
  
  Docs: README `## Observability`.

## Public API changes

No public API changes.

## Steps

1. Move any alert on a thrown 4xx `HttpError` from span error status to the `failure.code` attribute. The span still records `failure.code`, but its status is no longer error.

   Before:

   ```text
   span.status = error AND name starts with "http."
   ```

   After:

   ```text
   failure.code exists AND http.response.status_code < 500
   ```

   Alerts on status 500 or higher need no change.

## Verify

Throw a 4xx `HttpError` in a test and read the span. It has `failure.code` and no error status.

```sh
bun run test
```
